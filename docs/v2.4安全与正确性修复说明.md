# v2.4 安全与数据正确性修复说明

> 本次修复覆盖 P0(安全漏洞+数据正确性)与 P1(稳定性+性能)共 15 项问题。

## 一、P0 安全漏洞修复(7 项)

### 1.1 `create_task_validated` 未授权访问
**文件**: [create_task.py:131-133](../migration_app/create_task.py#L131)
**问题**: 该视图仅有 `@csrf_exempt`,无 `@login_required`,任何匿名用户可 POST 创建迁移任务。
**修复**: 增加 `@login_required` 装饰器。

### 1.2 `dashboard.py:105` bare except
**文件**: [dashboard.py:103-106](../migration_app/dashboard.py#L103)
**问题**: `except:` 不带类型,会捕获 `KeyboardInterrupt`/`SystemExit`,可能中断进程关闭。
**修复**: 改为 `except (EmptyPage, PageNotAnInteger):`。

### 1.3 `importlib.reload` 在线程内调用
**文件**: [dashboard.py:457-466](../migration_app/dashboard.py#L457)
**问题**: 在线程内重载 `migration_app.views` 模块会影响所有线程,导致其它线程持有的旧引用进入半重载状态,引发 `NameError`/`AttributeError`。
**修复**: 删除 `importlib.reload(v)` 调用,直接 `import` 后调用。

### 1.4 `start_task`/`cancel_task` 接受 GET 触发状态变更
**文件**: [dashboard.py:284-291,586-591](../migration_app/dashboard.py#L284)
**问题**: GET 请求不应有副作用,结合 `@csrf_exempt` 构成 CSRF 攻击向量(恶意页面 `<img src="/task/123/start">` 可启动任务)。
**修复**: `if request.method in ['POST', 'GET']:` → `if request.method == 'POST':`。

### 1.5 请求头/体写入日志(含 Cookie/密码)
**文件**: [dashboard.py:287-292,592-595](../migration_app/dashboard.py#L287)
**问题**: 将完整请求头(含 `Cookie`/`Authorization`)和原始请求体(可能含 password 字段)直接 INFO 级别写日志。
**修复**: 删除 `dict(request.headers)` 与 `request.body.decode('utf-8')` 调试日志,仅保留任务 ID/方法/用户名审计信息。

### 1.6 `str(e)` 直接返回前端
**文件**: views.py(9 处)、dashboard.py(2 处)
**问题**: 内部异常细节(数据库错误、文件路径、密码字段)泄露给前端。
**修复**: 全部替换为 `format_db_error(e)`,该函数会:
- 用正则脱敏 `password=xxx`/`PWD=xxx` 等敏感字段
- 截断超长错误消息(默认 500 字符)

### 1.7 挂载 `log_sanitize.SanitizeFilter` 到 LOGGING
**文件**: [log_sanitize.py:20-38](../migration_app/log_sanitize.py#L20)、[settings.py:424-434](../oracle2polardb_pg/settings.py#L424)
**问题**: `log_sanitize.py` 提供脱敏函数但未挂载到 LOGGING,业务日志中密码仍明文落盘。
**修复**:
1. 新增 `SanitizeFilter(logging.Filter)` 类,对 `record.msg` 与 `record.args` 自动脱敏
2. settings.py LOGGING 配置增加 `filters.sanitize` 并挂载到 console/slow_sql handler

## 二、P0 数据正确性修复(3 项)

### 2.1 TIMESTAMP(n) WITH TIME ZONE 落入 TEXT
**文件**: [views.py:1490-1511](../migration_app/views.py#L1490)
**问题**: Oracle `ALL_TAB_COLUMNS.DATA_TYPE` 返回 `'TIMESTAMP(6) WITH TIME ZONE'`(带精度),但 `type_map` key 是 `'TIMESTAMP WITH TIME ZONE'`(不带精度),**永不匹配**,最终落入 else 返回 TEXT,丢失时区信息。
**修复**: 在 `convert_oracle_to_pg_type` 入口处增加正则预处理:
- `TIMESTAMP(n) WITH TIME ZONE` → `TIMESTAMPTZ(n)`
- `TIMESTAMP(n) WITH LOCAL TIME ZONE` → `TIMESTAMPTZ(n)`(近似)
- 无精度 `TIMESTAMP WITH TIME ZONE` → `TIMESTAMPTZ`

同时新增 `PLS_INTEGER`→`INTEGER`、`JSON`→`JSONB`、`OBJECT`→`TEXT` 等缺失类型映射。

### 2.2 校验哈希格式不一致(系统性假阳性)
**文件**: [migration_validation.py:259-267](../migration_app/migration_validation.py#L259)
**问题**: Oracle `TO_CHAR(date)` → `'22-JUL-26'`,PG `date::text` → `'2026-07-22'`,相同数据哈希必不等,导致行哈希校验**几乎必然失败**。
**修复**: 两端统一使用 `to_char(col, 'YYYY-MM-DD HH24:MI:SS')` 格式化。

### 2.3 增量同步 UPDATE 检测哈希不一致
**文件**: [incremental_sync.py:333-344](../migration_app/incremental_sync.py#L333)
**问题**: 同 2.2,Oracle `TO_CHAR` 与 PG `::text` 格式化结果不同,触发无意义 UPDATE。
**修复**: 两端统一 `to_char(col, 'YYYY-MM-DD HH24:MI:SS')`。

## 三、P0 资源泄漏修复(1 项)

### 3.1 `migrate_routine` except 不 rollback 不 close
**文件**: [views.py:706-720](../migration_app/views.py#L706)
**问题**: 异常分支既不 rollback 也不 close,4 个 DB 对象泄漏 + PG 事务残留(后续 SQL 都报"当前事务被终止")。
**修复**: except 中调用 `rollback_quietly(pg_conn)` + `safe_close_db_resources(...)`。

## 四、P1 稳定性修复(4 项)

### 4.1 `get_task_executor` 全局初始化无锁
**文件**: [views.py:86-99](../migration_app/views.py#L86)
**问题**: `if ... is None` 检查与赋值不是原子操作,多线程并发调用可能创建多个 ThreadPoolExecutor,前几个被 GC 时 shutdown 会取消已提交任务。
**修复**: 增加 `_executor_lock = threading.Lock()`,双重检查锁定模式。

### 4.2 视图 SQL 转换缺失关键替换
**文件**: [oracle_sql_converter.py:96-102](../migration_app/oracle_sql_converter.py#L96)
**问题**: `convert_oracle_to_pg_view` 仅复用 `convert_oracle_to_pg_sql`(4 项基础替换),缺失 routine 的 6 项替换(ROWNUM/TO_DATE/TO_CHAR/TO_NUMBER/EXECUTE IMMEDIATE/DBMS_OUTPUT),导致视图 SQL 执行报错。
**修复**: `convert_oracle_to_pg_view` 改为复用 `convert_oracle_to_pg_routine`,获得全部 10 项替换。

### 4.3 `task.save()` 在锁外执行
**文件**: [views.py:1816-1818](../migration_app/views.py#L1816)
**问题**: `_flush_parallel_progress` 中 `task.save()` 在 `with state_lock` 块外执行,并发调用时字段可能被覆写后写入中间状态。
**修复**: `task.save()` 移入锁内。

### 4.4 `except Exception: pass` 关键路径吞掉取消检测失败
**文件**: [views.py:1046-1048](../migration_app/views.py#L1046)
**问题**: `task.refresh_from_db()` 失败被静默吞掉,导致任务无法响应取消请求。
**修复**: 改为 `except Exception as _cancel_err: logger.warning(...)`,记录但继续执行。

## 五、PL/SQL 转换增强(2 项)

### 5.1 TO_CHAR 格式参数丢失
**文件**: [oracle_sql_converter.py:122-141](../migration_app/oracle_sql_converter.py#L122)
**问题**: 原实现 `TO_CHAR(` → `CAST(`,导致 `TO_CHAR(date,'YYYY-MM-DD')` 变成 `CAST(date,'YYYY-MM-DD')` 语法错误。
**修复**:
- 单参数 `TO_CHAR(x)` → `x::text`
- 双参数 `TO_CHAR(x, 'fmt')` → `to_char(x, 'fmt')`(PG 原生支持,格式串不完全兼容但语法可执行)

### 5.2 新增 PL/SQL 专有语法检测
**文件**: [oracle_sql_converter.py:11-29](../migration_app/oracle_sql_converter.py#L11)
**新增检测**: FORALL、BULK COLLECT、PRAGMA、AUTONOMOUS_TRANSACTION、PACKAGE、DBMS_SQL、UTL_*、PIVOT/UNPIVOT、MODEL
**效果**: 这些 Oracle 专有语法会被加入 `manual_items` 人工审查清单,提醒用户需手动改写。
