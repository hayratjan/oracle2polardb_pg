# 迁移进度与监控

## 功能说明

迁移任务在执行过程中会更新**总进度**（`progress`）和**各对象明细进度**（`view_progress`），前端通过轮询任务详情接口即可展示进度条与百分比。

## 大表迁移进度优化（百万级数据）

当表或视图数据量较大（例如 100 万行以上）时，迁移耗时长，若进度一直为 0 会影响使用体验。本系统对以下两类任务做了优化：

### 1. 视图数据迁移到表（view_to_table）

- **总行数**：在开始拉取数据前会执行一次 `SELECT COUNT(*)` 获取当前视图总行数（大表时可能略慢，但只执行一次）。
- **进度计算**：按「已迁移行数 / 总行数」计算当前视图进度；总进度 = 各视图权重下的进度汇总。
- **节流保存**：进度不会每批都写库，而是约每提升 1% 或每 5 万行保存一次，减少数据库压力，同时保证界面上的进度会持续前进。
- **取消**：迁移过程中若用户点击取消，会在下一次进度保存时检测到并安全退出，已写入的数据会保留。

### 2. 单表迁移（table）

- **分批读取**：不再使用 `fetchall()` 一次性加载全部数据，改为 `fetchmany(5000)` 分批读取，避免百万级数据占满内存。
- **总行数**：同样在迁移前执行 `COUNT(*)` 得到总行数，用于计算进度百分比。
- **进度更新**：与 view_to_table 类似，按已迁移行数/总行数更新 `progress` 和 `view_progress`，并做节流保存（约每 1% 或每 5 万行写库一次）。

## 使用方法

1. 在任务列表或任务详情页启动迁移任务。
2. 任务详情页会展示总进度条（`task.progress`）及百分比。
3. 若任务类型为多对象或带明细进度，可在接口返回的 `view_progress` 中查看每个表/视图的进度、已迁移行数等（前端可按需展示）。
4. 大表迁移时请耐心等待；若需中止，使用任务详情页的「取消」功能，系统会在最近一次进度保存时安全停止。

## 接口说明

- **获取任务状态/进度**：`GET /api/tasks/{id}/` 或项目内提供的「任务状态」接口。
- 响应中的 `progress` 为 0–100 的总进度；`view_progress` 为各对象进度明细（含 `progress`、`log`、`total_rows`、`migrated_rows` 等）。
- 任务详情接口还会返回目标 PolarDB 信息：`postgres_connection_name`（连接名）、`postgres_database`（目标数据库）、`target_schema`（目标 Schema），以及 `source_objects`（源表/视图列表），便于任务详情页展示。

## 注意事项

- 总行数依赖 `COUNT(*)`，在 Oracle 中对于超大表可能较慢，属正常现象。
- 进度为「约每 1% 或每 5 万行」写库，因此界面上的百分比会阶梯式上升，而非每批都变。
- 列表分页已对任务、连接等列表使用固定排序，避免分页结果不一致的警告。
