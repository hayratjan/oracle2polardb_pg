# 迁移进度与监控

## 功能说明

迁移任务在执行过程中会更新**总进度**（`progress`）和**各对象明细进度**（`view_progress`），前端通过轮询任务详情接口即可展示进度条与百分比。

## 大表迁移进度优化（百万级数据）

当表或视图数据量较大（例如 100 万行以上）时，迁移耗时长，若进度一直为 0 会影响使用体验。本系统对以下两类任务做了优化：

### 1. 视图数据迁移到表（view_to_table）

- **总行数**：在开始拉取数据前会执行一次 `SELECT COUNT(*)` 获取当前视图总行数（大表时可能略慢，但只执行一次）。
- **分批与提交**：每批从 Oracle 拉取 1 万行（`arraysize=10000`），每 5 批向 PostgreSQL 提交一次（约 5 万行/commit），减少 Oracle 往返和 PG 事务开销以提升速度。
- **进度计算**：按「已迁移行数 / 总行数」计算当前视图进度；总进度 = 各视图权重下的进度汇总。
- **节流保存**：进度不会每批都写库，而是约每提升 1% 或每 5 万行保存一次，减少数据库压力，同时保证界面上的进度会持续前进。
- **取消**：迁移过程中若用户点击取消，会在下一次进度保存时检测到并安全退出，已写入的数据会保留。

### 2. 单表迁移（table）

- **分批读取**：使用 `fetchmany(20000)` 分批读取（arraysize=20000），减少 Oracle 往返次数。
- **批量提交**：每 5 批（约 10 万行）提交一次 PostgreSQL，减少 commit 次数以提升写入速度。
- **总行数**：在迁移前执行 `COUNT(*)` 得到总行数，用于计算进度百分比。
- **进度更新**：按已迁移行数/总行数更新 `progress` 和 `view_progress`，并做节流保存（约每 1% 或每 5 万行写库一次）。`view_progress` 仅存进度与行数，不存完整 log，减轻 DB 与接口压力。

### 3. 所有表迁移（all_tables）

- **不创建子任务**：选择「所有表」时，系统**不会**为每张表创建子任务，而是在**当前任务**中依次迁移该 Schema 下全部表，避免产生大量子任务（如数千张表时）。
- **进度展示**：总进度 `progress` 按「已处理表数 / 总表数」更新；`view_progress` 中提供 `current_table`（当前正在迁移的表名）、`current`、`total`（总表数）、`failed_count`（失败表数量），前端可直接展示「第 x/y 张表」或「正在迁移：XXX」。
- **失败与取消**：单张表失败时记录到日志并继续迁移下一张；全部完成后若有失败表则任务状态为「部分完成」（`partial`）。迁移过程中支持取消，取消后状态为「部分完成」，已迁移的表会保留。

## 使用方法

1. 在**任务列表**（`/tasks`）或任务详情页启动迁移任务。
2. 任务详情页会展示总进度条（`task.progress`）及百分比。
3. 若任务类型为多对象或带明细进度，可在接口返回的 `view_progress` 中查看每个表/视图的进度、已迁移行数等（前端可按需展示）。
4. 大表迁移时请耐心等待；若需中止，使用任务详情页的「取消」功能，系统会在最近一次进度保存时安全停止。

### 任务列表页功能（/tasks）

- **分页**：列表支持上一页/下一页，每页 20 条，底部显示「共 N 条、当前第 x–y 条」及页码；支持在「跳至 [页码] 页」输入框输入页码后点击「跳转」或回车跳转到指定页。
- **多选与全选**：表头复选框可全选当前页任务，每行复选框可勾选单个任务。
- **批量运行**：勾选一个或多个任务后，点击「批量运行」可同时启动所选任务（仅对待执行或可重跑状态生效）。
- **批量删除**：勾选后点击「批量删除」可删除所选任务（运行中的任务会被跳过）。
- 批量操作栏在有选中项时显示在表格上方，可随时「取消选择」清空勾选。

## 接口说明

- **任务列表（分页）**：`GET /api/tasks/?page=1&page_size=20`，返回 `count`、`next`、`previous`、`results`，前端任务列表页据此做分页与多选。
- **获取任务状态/进度**：`GET /api/tasks/{id}/` 或「任务状态」接口 `GET /api/tasks/{id}/status/`。
- **轻量轮询**：任务执行中前端每 5 秒轮询 `GET /api/tasks/{id}/status/?light=1`，仅返回 `status`、`progress`、`view_progress`（不含完整 log），显著减少响应体积与带宽，适合长时间迁移任务。
- 响应中的 `progress` 为 0–100 的总进度；`view_progress` 为各对象进度明细（含 `progress`、`total_rows`、`migrated_rows`；非 light 时可能含 `log`）。
- 任务详情接口还会返回目标 PolarDB 信息：`postgres_connection_name`（连接名）、`postgres_database`（目标数据库）、`target_schema`（目标 Schema），以及 `source_objects`（源表/视图列表），便于任务详情页展示。

## 注意事项

- 总行数依赖 `COUNT(*)`，在 Oracle 中对于超大表可能较慢，属正常现象。
- 进度为「约每 1% 或每 5 万行」写库，因此界面上的百分比会阶梯式上升，而非每批都变。
- 列表分页已对任务、连接等列表使用固定排序，避免分页结果不一致的警告。
- 长时间任务建议保持在任务详情页，前端会以 5 秒间隔轻量轮询进度；任务结束后会自动拉取一次完整详情以展示最终日志。
