# 前后端路由配置说明

## 路由架构

本项目采用前后端分离架构，前端使用 Vue Router，后端使用 Django REST Framework。

### 开发环境

- **前端**: Vue 开发服务器运行在 `http://localhost:5173`
- **后端**: Django 服务器运行在 `http://localhost:8000`
- **API**: 所有 API 请求通过 Vite 代理转发到 Django 后端

### 生产环境

- **前端**: Vue 构建后的静态文件由 Django 提供
- **后端**: Django 同时提供 API 和静态文件服务

## 后端路由 (Django)

### 主路由配置 (`oracle2polardb_pg/urls.py`)

```
http://localhost:8000/
├── admin/                    # Django 管理后台
├── api/                      # REST API 路由
│   ├── oracle-connections/   # Oracle 连接管理
│   ├── postgres-connections/ # PostgreSQL 连接管理
│   ├── tasks/                # 迁移任务管理
│   ├── schemas/              # Schema 查询
│   ├── database-objects/     # 数据库对象查询
│   ├── postgres-databases/   # PostgreSQL 数据库列表
│   ├── filesystem/directories/ # 文件系统浏览
│   ├── database-info/        # 数据库信息
│   ├── oracle/               # Oracle 相关 API
│   ├── polardb/              # PolarDB 相关 API
│   ├── postgres/             # PostgreSQL 连接 API
│   ├── config/               # 配置 API
│   ├── logs/                 # 日志 API
│   └── help/                 # 帮助文档
└── (开发环境重定向到 Vue 开发服务器)
```

### 应用路由说明 (`migration_app/urls.py`)

- 主 `urls.py` 已配置 `path('api/', include('migration_app.urls'))`，故在 `migration_app/urls.py` 中无需再加 `api/` 前缀。
- Router 注册使用相对路径，如 `r'oracle-connections'`。

#### REST API ViewSets

- `GET/POST /api/oracle-connections/`、`GET/PUT/DELETE /api/oracle-connections/{id}/`
- `GET/POST /api/postgres-connections/`、`GET/PUT/DELETE /api/postgres-connections/{id}/`
- `GET/POST /api/tasks/`、`GET/PUT/DELETE /api/tasks/{id}/`
- `POST /api/tasks/{id}/start/`、`POST /api/tasks/{id}/cancel/`
- `GET /api/tasks/{id}/status/`、`GET /api/tasks/{id}/info/`
- `POST /api/tasks/{id}/switch_database/`

#### 自定义 API 端点

- Schema/对象/数据库：`/api/schemas/`、`/api/database-objects/`、`/api/postgres-databases/`、`/api/database-info/`
- Oracle：`/api/oracle/schemas/`、`/api/oracle/tables/`、`/api/oracle/users/`、`test-connection`、`save-connection`、`delete-connection`
- PolarDB：`/api/polardb/schemas/`、`/api/polardb/tables/`、`/api/polardb/users/`
- PostgreSQL 连接：`/api/postgres/test-connection/`、`save-connection/`、`delete-connection/`、`edit-connection/`
- 配置与日志：`/api/config/migration/`、`/api/config/system/`、`/api/logs/`、`/api/help/`
- `POST /api/create-task/`：创建任务（带验证）

#### 旧 HTML 视图（向后兼容）

- `/app/`、`/app/tasks/`、`/app/task/create/` 等保留在 `/app/` 下。

## 前端路由 (Vue Router)

### 路由配置 (`frontend/src/router/index.ts`)

| 路径 | 名称 | 说明 |
|------|------|------|
| `/` | Home | 首页，最近任务与连接统计 |
| `/tasks` | TaskList | 任务列表 |
| `/task/create` | CreateTask | 创建任务 |
| `/task/:id` | TaskDetail | 任务详情与日志 |
| `/oracle` | OracleDatabase | Oracle 连接管理 |
| `/postgres` | PostgresDatabase | PostgreSQL 连接管理 |
| `/config` | Config | 系统配置与日志 |

## API 与代理配置

- **API 客户端**：`frontend/src/api/client.ts`。`baseURL` 取 `VITE_API_BASE_URL`，三态语义：
  - 变量**未定义** → 回落 `http://localhost:8000`（本机分开跑前后端）；
  - 显式设为**空串** → 同源相对路径 `/api/`（合并镜像部署，Django 自己就是入口）；
  - 设为某个 URL → 以它为准（前后端分开部署到不同域名）。
  区分靠 `=== undefined` 判断：早先用 `||` 兜底会把空串也吞成 localhost，导致"同源构建"出来的前端仍打本机地址。
- **Vite 代理**：`/api` 代理到 `http://localhost:8000`，开发环境避免 CORS 问题。
- **生产静态与深层链接**：`/assets/*`、`index.html` 由 WhiteNoise 直出，非真实前缀的 GET 由 `urls.py` 的 `spa_fallback` 回退到 `index.html`（`api/admin/static/media/healthz/readyz` 前缀仍返回 404）。

## 开发流程

1. 后端：`uv run manage.py runserver`（或 `python manage.py runserver`），默认 `http://localhost:8000`。
2. 前端：`cd frontend && pnpm dev`，默认 `http://localhost:5173`。
3. 访问前端应用后，前端请求经 Vite 代理到后端 `/api/*`。

## 生产部署

1. 前端：`cd frontend && pnpm build`，产物在 `frontend/dist/`。
2. 静态文件：`python manage.py collectstatic`。
3. 在 `settings.py` 中设置 `DEBUG = False`、`ALLOWED_HOSTS`。
4. 使用 gunicorn 等运行：`gunicorn oracle2polardb_pg.wsgi:application`。

## 常见问题

- **开发环境 CORS**：由 Vite 代理转发，无需单独配置 CORS。
- **新增 API**：在 `migration_app/api.py` 与 `urls.py` 添加，并在 `frontend/src/api/index.ts` 增加调用。
- **新增前端页面**：在 `frontend/src/views/` 建组件，在 `router/index.ts` 添加路由，并在导航中加链接。
